## rc.3 接口审计

运行 `pnpm api:audit` 后，48/48 个操作均收到：

- HTTP 状态：`308 Permanent Redirect`
- 跳转目标：`https://47.106.168.39/api/...`
- 浏览器继续访问 HTTPS IP 时：`ERR_SSL_PROTOCOL_ERROR`

因此当前无法用提供的 5 个账号完成服务端业务响应验收。阻塞发生在 TLS 握手之前，不是前端字段、CSRF、Cookie 或账号密码错误。

## 交付前服务端必须处理

以下方案任选一个：

1. 提供带有效域名和证书的 HTTPS API Base URL；
2. 关闭 `47.106.168.39` 的 HTTP 到 HTTPS 强制跳转；
3. 为该 IP 配置能够完成握手的 TLS 默认站点。

2026-09-17 复测补充证据（服务端为 Caddy，端口 80/443）：

- `http://47.106.168.39/api/v1/auth/csrf` → `308 Permanent Redirect`，`Location: https://47.106.168.39/api/v1/auth/csrf`（`Server: Caddy`）；
- `https://47.106.168.39` TLS 握手被服务端直接拒绝：`tlsv1 alert internal error (alert 80)`，**未返回任何证书**——裸 IP 无法签发证书，443 上不存在可用站点，加 `-k` 跳过校验也无法连接；
- 3000/8000/8080/8888/9000/9090/2015/8443 等常见端口均未开放，不存在可绕行的 HTTP 入口；
- 注意：`308` 为永久重定向，浏览器会缓存（Network 面板显示 disk cache）。服务端修复后，浏览器需强制刷新（Ctrl+Shift+R）或在 DevTools 勾选 Disable cache，否则仍会命中旧的 308 缓存继续跳转失败。

入口修复后，前端不需要恢复静态数据；重新运行 `pnpm api:audit`，再执行登录、发布 Tag、申请、接受、聊天、竞价链路即可。
